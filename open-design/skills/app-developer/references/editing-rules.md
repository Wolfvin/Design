# Editing Rules — React + Tauri Source Files

Conventions for editing source files in the app-developer workflow.

## General Rules

1. **Read before write.** Always read a file in full before editing it.
2. **Minimal diffs.** Change only what is necessary. Avoid reformatting
   unrelated code.
3. **Consistent style.** Match the existing code style in each file:
   - Indentation (tabs vs spaces)
   - Quote style (single vs double)
   - Semicolons (present or absent)
   - Trailing commas
4. **No dead code.** Do not leave commented-out blocks. If code must be
   preserved temporarily, add a `// TODO: remove after <date>` annotation.

## React Component Rules

### File structure

```tsx
// 1. Imports (grouped: react, libraries, internal, types)
import React, { useState, useEffect } from 'react';
import { motion } from 'framer-motion';
import { useAuth } from '@/hooks/useAuth';
import type { User } from '@/types/user';

// 2. Types (inline or imported)
interface HeaderProps {
  title: string;
  subtitle?: string;
}

// 3. Component
export function Header({ title, subtitle }: HeaderProps) {
  // hooks
  const auth = useAuth();

  // state
  const [isOpen, setIsOpen] = useState(false);

  // effects
  useEffect(() => {
    // ...
  }, []);

  // handlers
  const handleToggle = () => setIsOpen((v) => !v);

  // render
  return (
    <header>
      <h1>{title}</h1>
      {subtitle && <p>{subtitle}</p>}
    </header>
  );
}
```

### Naming

- Components: **PascalCase** (`UserCard.tsx`)
- Hooks: **camelCase with `use` prefix** (`useAuth.ts`)
- Utilities: **camelCase** (`formatDate.ts`)
- Types: **PascalCase** (`User`, `AuthState`)
- CSS modules: **PascalCase** (`UserCard.module.css`)

### Exports

- Use **named exports** for components. Avoid default exports.
- One component per file. Small helper components may share a file if
  tightly coupled.

### Props

- Always define an interface for props, even if there's only one.
- Use optional properties (`?`) for props with sensible defaults.
- Destructure props in the function signature.

### State

- Prefer `useState` for local state.
- Use Zustand for shared/client state.
- Use TanStack Query for server state.
- Never store derived state — compute it during render.

## CSS Module Rules

- One `.module.css` per component.
- Class names: **camelCase**.
- Use design tokens (`var(--bg)`, `var(--accent)`, etc.).
- No global selectors.
- No `!important`.

```css
.card {
  background: var(--bg-secondary);
  border: 1px solid var(--border);
  border-radius: var(--radius);
  padding: 1rem;
}

.title {
  font-family: var(--font-display);
  font-weight: 600;
  color: var(--fg);
}
```

## Tauri Integration Rules

### IPC Commands

Define Rust commands in `src-tauri/src/commands/`:

```rust
#[tauri::command]
pub fn get_user(id: String) -> Result<User, String> {
    // ...
}
```

Register in `src-tauri/src/main.rs`:

```rust
.invoke_handler(tauri::generate_handler![
    commands::get_user,
    commands::save_user,
])
```

### Frontend Bindings

Create typed bindings in `src/lib/tauri/`:

```typescript
// src/lib/tauri/users.ts
import { invoke } from '@tauri-apps/api/core';
import type { User } from '@/types/user';

export async function getUser(id: string): Promise<User> {
  return invoke<User>('get_user', { id });
}
```

### Error Handling

- Rust commands return `Result<T, String>`.
- Frontend bindings wrap `invoke` in try/catch.
- Never expose raw Rust errors to the UI — transform them into
  user-friendly messages.

## Import Order

Group imports with blank lines between groups:

1. React / framework
2. External libraries
3. Internal modules (`@/...`)
4. Types (`type` imports)

```typescript
import React, { useState } from 'react';
import { motion } from 'framer-motion';
import { invoke } from '@tauri-apps/api/core';

import { useAuth } from '@/hooks/useAuth';
import { Button } from '@/components/ui/Button';

import type { User } from '@/types/user';
```

## Testing Conventions

Tests are not generated by this skill. However, when editing files that
have existing tests, ensure your changes do not break them:

- Do not change public API signatures without updating test imports.
- Do not remove exported functions that tests depend on.
